# О проекте

## Каталог асан традиционных школ йоги

Каталог асан традиционных школ йоги — это веб-приложение, в котором знания об
асанах собраны не как «один правильный вариант», а как набор представлений из
разных книг и традиций. Каждая запись об асане жёстко привязана к источнику
(книге, публикации, традиции), поэтому одна и та же поза из разных школ
сосуществует как **разные записи** и не теряет авторства.

---

## Идея

Существующие справочники по асанам обычно страдают двумя проблемами:

- знание «обезличено» — нет понимания, из какой книги взята формулировка;
- разные традиции «склеены» в один обобщённый вариант, и нюансы теряются.

Этот проект решает обе задачи: запись определяется парой *название + источник*,
а похожие представления одной асаны в разных школах связываются между собой
явной онтологической связью `isSameAs`.

---

## Из чего состоит система

Каталог собран как набор связанных сервисов в `docker compose`:

- **Каталог-сервис (`asana-dict-service`)** — FastAPI-бэкенд + React-фронтенд.
  Управляет асанами, названиями, источниками, фотографиями, пользователями,
  модерацией и интегрируется с остальными сервисами.
- **PostgreSQL** — служебные данные: пользователи, очередь модерации,
  предложения ИИ, контент страниц «О проекте» и «Инструкции».
- **OWL-онтология** — основная база знаний (классы `Asana`, `AsanaName`,
  `Source`, `Photo`, связи `isSameAsObject`). Хранится в файле онтологии
  и загружается каталог-сервисом.
- **MinIO** — объектное S3-хранилище для фотографий асан.
- **Nginx** — реверс-прокси: отдаёт фронтенд, проксирует API и публичные
  URL изображений из MinIO.
- **AI-сервис (`asana-network-service`)** — отдельный FastAPI-сервис с
  моделью YOLO (yoga-82) и перцептивным хешем (pHash) для поиска одинаковых
  фотографий и одинаковых поз. Используется страницей «ИИ — модерация связей».

## Ключевые особенности

### Привязка к источнику

Каждая асана существует не сама по себе, а в контексте конкретной книги или
публикации. Это даёт честное представление: видно, как один и тот же образ
позы изложен у разных авторов.

### Множественные представления одной асаны

Если та же поза встречается в разных источниках, в каталоге появляются
**разные записи**. Чтобы пользователь видел «семью» представлений, между
такими записями устанавливаются связи `isSameAs`. Связи можно ставить
вручную (эксперт/администратор) или через ИИ-модерацию.

### Поиск, навигация, фильтры

- нечёткий поиск по русским названиям, санскриту и транслитерации;
- алфавитная навигация;
- фильтрация по источнику;
- список похожих асан на странице каждой асаны.

### Фотографии асан

К одной асане может быть несколько фото из разных источников. Фото
хранятся в MinIO; в онтологии хранится только путь — это упрощает замену
файла без нарушения структуры данных.

### ИИ-модерация связей

Отдельная вкладка для эксперта и администратора. ИИ-сервис проходит по
всем фото в каталоге и предлагает пары записей-кандидатов на `isSameAs` по
двум основаниям:

- *«одинаковое фото»* — перцептивный хеш (pHash, устойчивый к повороту):
  тот же снимок используется в двух разных карточках;
- *«та же поза»* — совпадение топ-1 класса классификатора YOLO yoga-82
  выше порога уверенности.

Каждое предложение проходит ручную проверку: эксперт нажимает «Подтвердить»
(тогда создаётся связь `isSameAsObject` в онтологии) или «Отклонить».

### Очередь модерации импорта

При импорте Excel в каталог проблемные строки (несовпавшие названия,
дубликаты, ошибки данных) автоматически попадают в раздел «Требует
модерации». Эксперт может привязать их к существующей асане, создать
новую, экспортировать в Excel для исправления или пометить решёнными.

## Онтологический подход

Знания об асанах хранятся в OWL-онтологии. Это даёт:

- **формальную структуру** — классы и связи определены явно
  (`Asana`, `AsanaName`, `Source`, `Photo`, `isSameAsObject`);
- **расширяемость** — новые атрибуты и связи добавляются без переписывания
  бэкенда;
- **переносимость** — выгрузка онтологии в стандартном формате OWL
  совместима со сторонними семантическими инструментами (Protégé и т.п.);
- **целостность данных** — обновление онтологии проходит проверки.

Файл онтологии можно скачать и загрузить обратно через раздел «Настройки»
(только администратор).

---

## Роли пользователей

- **Обычный пользователь / гость** — просмотр каталога, поиск, фильтры,
  страницы «О проекте». Регистрация — по согласованию с администратором.
- **Эксперт** — добавление и редактирование асан, источников, фотографий;
  работа с очередью модерации; работа с ИИ-модерацией связей; импорт
  данных из Excel.
- **Администратор** — всё то же, плюс управление пользователями, загрузка
  и выгрузка онтологии, редактирование текста этой страницы и страницы
  «Инструкции для экспертов», полная очистка очередей модерации.

## Стек технологий

- **Backend каталога**: Python 3.12, FastAPI, SQLAlchemy, rdflib, Pydantic.
- **AI-сервис**: Python 3.12, FastAPI, Ultralytics YOLO (CPU-сборка),
  imagehash (pHash), Pillow, OpenCV.
- **Frontend**: React 18 + Vite, React Router, axios.
- **Хранение**: PostgreSQL (служебные данные), MinIO (изображения),
  OWL-файл (онтология).
- **Инфраструктура**: Docker, Docker Compose, Nginx.

---

## Направления развития

- наполнение каталога новыми источниками и традициями;
- расширение ИИ-модуля: дообучение классификатора на собственных данных,
  эмбеддинги поз, поиск визуально похожих, а не только идентичных, фото;
- мобильное приложение поверх того же API (есть прототип Android-клиента);
- образовательные сценарии: подборки асан, рекомендации, тесты на основе
  связей `isSameAs`;
- публичный API и SPARQL-эндпоинт к онтологии.

---

## Философия

Мы не стремимся свести многообразие школ йоги к одному «каноническому»
варианту. Цель — собрать рядом разные представления, честно указав, откуда
взято каждое из них, и дать инструмент, чтобы видеть, где они совпадают,
а где расходятся. Решение, какому источнику доверять, остаётся за
читателем.
