## Слайд 2: Технологический стек
Приложение разработано с использованием современных технологий Android. В качестве языка программирования выбран Kotlin - это современный язык с поддержкой корутин для асинхронных операций и встроенной защитой от null-указателей.

Для создания пользовательского интерфейса используется Jetpack Compose - это декларативный фреймворк, который позволяет описывать UI как функции. Вместо императивного подхода, где мы говорим "создай кнопку, установи текст, добавь обработчик", мы просто описываем, как должен выглядеть интерфейс при определенном состоянии.

Архитектура приложения построена на паттерне MVVM - Model-View-ViewModel. Это обеспечивает четкое разделение между логикой приложения и его представлением.

Для управления зависимостями используется Hilt - это библиотека, которая автоматически создает и внедряет зависимости, что значительно упрощает код и тестирование.

Для работы с сетью применяется Retrofit - это библиотека, которая позволяет описывать API как интерфейсы с аннотациями, а сама библиотека генерирует реализацию во время компиляции.

## Слайд 3: Архитектура MVVM - как это работает
Архитектура MVVM состоит из трех уровней. На верхнем уровне находится View - это UI слой, представленный экранами на Jetpack Compose. Экран только отображает данные и обрабатывает действия пользователя. Он подписывается на StateFlow из ViewModel и автоматически обновляется при изменении состояния.

ViewModel - это слой бизнес-логики. Он хранит состояние UI в StateFlow, выполняет бизнес-логику, вызывает методы Repository для получения данных и обрабатывает ошибки, преобразуя их в понятные UI-состояния.

Repository - это слой данных. Он абстрагирует источник данных - это может быть API, локальная база данных или кэш. Repository преобразует ответы API в модели данных приложения, обрабатывает сетевые ошибки и возвращает Result для обработки успеха или ошибки.

Такая архитектура обеспечивает разделение ответственности - каждый слой знает только о своей задаче. Это упрощает тестирование - можно тестировать ViewModel отдельно от UI, и Repository отдельно от ViewModel. Также это позволяет переиспользовать код - один Repository может использоваться несколькими ViewModel.

## Слайд 4: Jetpack Compose - декларативный UI
Jetpack Compose работает по принципу декларативного программирования. UI описывается как функции, которые принимают состояние и возвращают интерфейс. При изменении состояния Compose автоматически перерисовывает только измененные части интерфейса, используя механизм recomposition - умную перерисовку только нужных компонентов.

Composable функции помечаются специальной аннотацией @Composable. Они могут вызывать другие Composable функции, создавая иерархию компонентов. Эти функции автоматически подписываются на StateFlow через collectAsStateWithLifecycle и обновляются только при изменении наблюдаемых данных.

Приложение использует Material Design 3 - это современная дизайн-система от Google. Она предоставляет готовые компоненты - карточки, кнопки, поля ввода, которые уже имеют правильные размеры, отступы и анимации. Также поддерживаются адаптивные цвета и темы, включая темную тему.

Преимущества такого подхода - значительно меньше кода по сравнению с традиционным View-системой, автоматическая оптимизация производительности, и реактивность - UI автоматически обновляется при изменении данных.

## Слайд 5: Работа с сетью - Retrofit и OkHttp
Retrofit позволяет описывать API как интерфейсы с аннотациями. Например, метод с аннотацией @GET("api/asanas") автоматически преобразуется в HTTP GET запрос к этому endpoint. Retrofit генерирует реализацию интерфейса во время компиляции, что обеспечивает типобезопасность. Также используется Gson для автоматической десериализации JSON ответов в Kotlin объекты.

OkHttp Interceptors - это мощный механизм для перехвата и модификации запросов и ответов. В приложении используется AuthInterceptor, который автоматически добавляет JWT токен к каждому запросу. Он читает токен из DataStore перед каждым запросом, что гарантирует использование актуального токена. LoggingInterceptor логирует все запросы и ответы для отладки. Также interceptor обрабатывает ошибки 401 и автоматически перенаправляет пользователя на экран входа.

Обработка ошибок организована на нескольких уровнях. Repository оборачивает ответы API в Result - это sealed class, который может быть либо Success с данными, либо Failure с ошибкой. ViewModel обрабатывает Result и обновляет UI состояние соответственно. UI показывает понятные сообщения об ошибках пользователю.

Все сетевые запросы выполняются в корутинах - это легковесные потоки Kotlin, которые не блокируют UI поток. Это означает, что приложение остается отзывчивым даже во время загрузки данных.

## Слайд 6: Управление состоянием - StateFlow и ViewModel
StateFlow - это поток данных, который хранит текущее значение. Он автоматически уведомляет всех подписчиков об изменениях и гарантирует, что подписчик получит последнее значение при подписке. StateFlow является thread-safe - его можно обновлять из любого потока.

ViewModel переживает изменения конфигурации, такие как поворот экрана. Это означает, что данные не теряются при повороте устройства. ViewModel использует viewModelScope для управления жизненным циклом корутин - все корутины автоматически отменяются при уничтожении ViewModel, что предотвращает утечки памяти.

Состояния UI представлены через sealed classes - это специальный тип классов в Kotlin, который позволяет создавать ограниченные иерархии классов. В приложении используются состояния: Loading - загрузка данных, Success - успешная загрузка с данными, Error - ошибка с сообщением, и Empty - пустой результат.

Как это работает на практике: ViewModel вызывает метод Repository, Repository возвращает Result, ViewModel обновляет StateFlow в зависимости от результата, и UI автоматически перерисовывается при изменении StateFlow. Это создает реактивный поток данных от источника до интерфейса.

## Слайд 7: Навигация - Navigation Compose
Navigation Compose работает через NavHost - это контейнер, который содержит все возможные маршруты, то есть экраны приложения. Каждый маршрут определяется через composable функцию. Параметры передаются через path или query параметры, и Navigation Compose автоматически управляет back stack - стеком экранов для кнопки "Назад".

Навигация является типобезопасной - маршруты определяются как строки, параметры извлекаются из backStackEntry.arguments. Для специальных символов в параметрах используется URL encoding при передаче и автоматическое декодирование при получении.

Навигация с параметрами поддерживает path параметры, например asana_detail/{asanaId}, где asanaId автоматически извлекается из пути. Также поддерживаются query параметры, например search?query=text. Navigation Compose поддерживает deep linking - возможность открывать конкретные экраны по ссылкам.

Управление жизненным циклом ViewModel интегрировано с навигацией. ViewModel создается через hiltViewModel() и привязан к маршруту. При переходе на другой экран ViewModel сохраняется, а при возврате переиспользуется, если маршрут находится в back stack. Это оптимизирует использование памяти.

## Слайд 8: Загрузка изображений - Coil
Coil - это библиотека для загрузки изображений, написанная на корутинах. Она обеспечивает асинхронную загрузку изображений, автоматическое кэширование в памяти и на диске, поддержку различных форматов и автоматическое масштабирование под размер экрана.

Lazy Loading - это техника, при которой изображения загружаются только когда становятся видимыми. LazyColumn автоматически определяет видимые элементы, и Coil отменяет загрузку, если элемент скрылся. Это значительно экономит трафик и память, особенно при работе с большими списками изображений.

Кэширование организовано на двух уровнях - память и диск. Изображения сначала проверяются в кэше памяти, затем на диске, и только потом загружаются из сети. Автоматическая очистка происходит при нехватке памяти. Также поддерживается ETag для проверки обновлений изображений на сервере.

При загрузке показывается placeholder - временное изображение, которое отображается пока идет загрузка. При ошибке показывается error изображение. Поддерживаются плавные переходы между состояниями и анимации, что создает приятный пользовательский опыт.

## Слайд 9: Dependency Injection - Hilt
Hilt - это библиотека для dependency injection, построенная на базе Dagger. Она генерирует код для создания и внедрения зависимостей во время компиляции, что обеспечивает производительность и типобезопасность. Аннотации определяют области видимости - Singleton для объектов, которые должны существовать в единственном экземпляре, Activity для объектов, привязанных к Activity, ViewModel для ViewModel.

Модули, такие как NetworkModule и DatabaseModule, определяют как создавать объекты. Например, NetworkModule создает Retrofit с базовым URL, добавляет interceptors, настраивает конвертеры. Модули могут предоставлять несколько реализаций одного интерфейса, что полезно для тестирования.

Внедрение зависимостей происходит автоматически. Аннотация @Inject в конструкторе автоматически внедряет зависимости. @HiltViewModel создает ViewModel с зависимостями. Функция hiltViewModel() получает ViewModel из графа зависимостей. Все зависимости создаются один раз и переиспользуются, что оптимизирует использование памяти.

Преимущества такого подхода - легкое тестирование, так как можно заменить зависимости на mock-объекты, централизованная конфигурация, автоматическое управление жизненным циклом, и значительно меньше boilerplate кода.

## Слайд 10: Итоги и особенности реализации
В заключение, хочу отметить ключевые технические решения, которые были реализованы в приложении.

Асинхронность - все долгие операции выполняются в корутинах, UI поток никогда не блокируется, и есть автоматическая отмена при уничтожении ViewModel.

Обработка ошибок организована на нескольких уровнях - Repository, ViewModel и UI. Пользователь всегда видит понятные сообщения, есть retry логика для сетевых запросов, и graceful degradation при ошибках.

Производительность оптимизирована через lazy loading списков и изображений, кэширование данных и изображений, минимизацию recomposition в Compose, и эффективное использование памяти.

Безопасность обеспечивается через HTTPS для всех запросов, JWT токены хранятся в безопасном хранилище DataStore, есть автоматическое обновление токенов, и валидация данных на клиенте и сервере.

В результате получилось современное, производительное, безопасное Android-приложение с чистой архитектурой, которое легко поддерживать и расширять.
