## Слайд 2: Технологический стек

## Слайд 3: Архитектура MVVM - как это работает
**Трехуровневая архитектура**

**View (UI Layer):**
- Экраны на Jetpack Compose
- Только отображение данных и обработка пользовательских действий
- Подписывается на StateFlow из ViewModel
- Автоматически обновляется при изменении состояния

**ViewModel (Business Logic Layer):**
- Хранит состояние UI в StateFlow
- Выполняет бизнес-логику
- Вызывает методы Repository для получения данных
- Обрабатывает ошибки и преобразует их в UI-состояния

**Repository (Data Layer):**
- Абстрагирует источник данных (API, локальная БД)
- Преобразует ответы API в модели данных
- Обрабатывает сетевые ошибки
- Возвращает Result для обработки успеха/ошибки

**Преимущества:** Разделение ответственности, тестируемость, переиспользование

## Слайд 4: Jetpack Compose - декларативный UI
**Как работает декларативный подход**

**Принцип работы:**
- UI описывается как функции, которые принимают состояние и возвращают интерфейс
- При изменении состояния Compose автоматически перерисовывает только измененные части
- Использует механизм recomposition - умная перерисовка только нужных компонентов

**Composable функции:**
- Функции помечаются аннотацией @Composable
- Могут вызывать другие Composable функции
- Автоматически подписываются на StateFlow через collectAsStateWithLifecycle
- Обновляются только при изменении наблюдаемых данных

**Material Design 3:**
- Готовые компоненты (Card, Button, TextField)
- Адаптивные цвета и темы
- Встроенные анимации и переходы
- Поддержка темной темы

**Преимущества:** Меньше кода, автоматическая оптимизация, реактивность

## Слайд 5: Работа с сетью - Retrofit и OkHttp
**Как работает взаимодействие с API**

**Retrofit:**
- Создает интерфейсы с аннотациями для описания API endpoints
- Генерирует реализацию интерфейса во время компиляции
- Преобразует вызовы методов в HTTP запросы
- Использует Gson для автоматической десериализации JSON в Kotlin объекты

**OkHttp Interceptors:**
- AuthInterceptor автоматически добавляет JWT токен к каждому запросу
- Читает токен из DataStore перед каждым запросом
- LoggingInterceptor логирует все запросы и ответы для отладки
- Обрабатывает ошибки 401 и автоматически перенаправляет на экран входа

**Обработка ошибок:**
- Repository оборачивает ответы в Result (Success/Failure)
- ViewModel обрабатывает Result и обновляет UI состояние
- UI показывает понятные сообщения об ошибках пользователю

**Асинхронность:** Все сетевые запросы выполняются в корутинах, не блокируя UI поток

## Слайд 6: Управление состоянием - StateFlow и ViewModel
**Как работает реактивное состояние**

**StateFlow:**
- Поток данных, который хранит текущее значение
- Автоматически уведомляет всех подписчиков об изменениях
- Гарантирует, что подписчик получит последнее значение при подписке
- Thread-safe - можно обновлять из любого потока

**ViewModel:**
- Переживает изменения конфигурации (поворот экрана)
- Использует viewModelScope для управления жизненным циклом корутин
- Хранит состояние UI в StateFlow
- Предоставляет методы для изменения состояния

**UI States (Sealed Classes):**
- Loading - загрузка данных
- Success - успешная загрузка с данными
- Error - ошибка с сообщением
- Empty - пустой результат

**Как это работает:**
1. ViewModel вызывает метод Repository
2. Repository возвращает Result
3. ViewModel обновляет StateFlow в зависимости от результата
4. UI автоматически перерисовывается при изменении StateFlow

## Слайд 7: Навигация - Navigation Compose
**Как работает типобезопасная навигация**

**Принцип работы:**
- NavHost содержит все возможные маршруты (экраны)
- Каждый маршрут определяется через composable функцию
- Параметры передаются через path или query параметры
- Navigation Compose автоматически управляет back stack

**Type-safe навигация:**
- Маршруты определяются как строки
- Параметры извлекаются из backStackEntry.arguments
- URL encoding для специальных символов в параметрах
- Автоматическое декодирование при получении

**Навигация с параметрами:**
- Path параметры: asana_detail/{asanaId}
- Query параметры: search?query=text
- Deep linking поддержка
- Автоматическая обработка back button

**Управление жизненным циклом:**
- ViewModel создается через hiltViewModel() и привязан к маршруту
- При переходе на другой экран ViewModel сохраняется
- При возврате ViewModel переиспользуется, если маршрут в back stack

## Слайд 8: Загрузка изображений - Coil
**Как работает эффективная загрузка изображений**

**Coil (Coroutine Image Loader):**
- Асинхронная загрузка изображений в корутинах
- Автоматическое кэширование в памяти и на диске
- Поддержка различных форматов (JPEG, PNG, WebP, GIF)
- Автоматическое масштабирование под размер экрана

**Lazy Loading:**
- Изображения загружаются только когда становятся видимыми
- LazyColumn автоматически определяет видимые элементы
- Coil отменяет загрузку, если элемент скрылся
- Экономия трафика и памяти

**Кэширование:**
- Двухуровневое кэширование: память + диск
- Автоматическая очистка при нехватке памяти
- Проверка кэша перед загрузкой из сети
- Поддержка ETag для проверки обновлений

**Placeholder и Error:**
- Показ placeholder во время загрузки
- Показ error изображения при ошибке
- Плавные переходы между состояниями
- Поддержка анимаций

## Слайд 9: Dependency Injection - Hilt
**Как работает автоматическое управление зависимостями**

**Hilt (на базе Dagger):**
- Генерирует код для создания и внедрения зависимостей во время компиляции
- Аннотации определяют области видимости (Singleton, Activity, ViewModel)
- Автоматически создает граф зависимостей

**Модули (NetworkModule, DatabaseModule):**
- Определяют как создавать объекты (Retrofit, Repository, ViewModel)
- Могут предоставлять несколько реализаций одного интерфейса
- Настраивают зависимости (базовый URL, interceptors, конвертеры)

**Внедрение зависимостей:**
- @Inject в конструкторе автоматически внедряет зависимости
- @HiltViewModel создает ViewModel с зависимостями
- hiltViewModel() получает ViewModel из графа зависимостей
- Все зависимости создаются один раз и переиспользуются

**Преимущества:**
- Легкое тестирование (можно заменить зависимости на mock)
- Централизованная конфигурация
- Автоматическое управление жизненным циклом
- Меньше boilerplate кода

## Слайд 10: Итоги и особенности реализации
**Ключевые технические решения**

**Асинхронность:**
- Все долгие операции выполняются в корутинах
- UI поток никогда не блокируется
- Автоматическая отмена при уничтожении ViewModel

**Обработка ошибок:**
- Многоуровневая обработка (Repository → ViewModel → UI)
- Понятные сообщения для пользователя
- Retry логика для сетевых запросов
- Graceful degradation при ошибках

**Производительность:**
- Lazy loading списков и изображений
- Кэширование данных и изображений
- Минимизация recomposition в Compose
- Эффективное использование памяти

**Безопасность:**
- HTTPS для всех запросов
- JWT токены в безопасном хранилище (DataStore)
- Автоматическое обновление токенов
- Валидация данных на клиенте и сервере

**Результат:** Современное, производительное, безопасное Android-приложение с чистой архитектурой
