# Практическая работа 2. Конструктивная модель стоимости COCOMO

## Цель работы
Изучить алгоритмы различных уровней конструктивных моделей Б. Боэма и автоматизировать процесс расчета экономических показателей проекта по разработке программного продукта "Каталог асан".

## Описание проекта

**Проект:** Веб-приложение "Каталог асан" - информационная система для хранения и управления информацией об асанах йоги.

**Основные компоненты:**
- Backend API (Python, FastAPI) - ~8000 строк кода
- Frontend (React, JavaScript) - ~5000 строк кода
- Онтология (OWL/RDF) - ~500 строк
- База данных (PostgreSQL) - схемы и миграции
- Инфраструктура (Docker, Nginx) - ~300 строк конфигурации

**Общий объем:** ~13800 строк исходного кода (13.8 KSLOC)

**Технологии:**
- Python 3.9+, FastAPI, SQLAlchemy, RDFLib
- React 18, JavaScript (ES6+), Vite
- PostgreSQL, MinIO (S3)
- Docker, Nginx

## 1. Базовый уровень COCOMO

### 1.1. Определение типа проекта

**Анализ проекта "Каталог асан":**

Проект относится к **полунезависимому типу**, так как:
- Команда имеет средний опыт работы с подобными системами
- Используются современные технологии (FastAPI, React), но не все члены команды имеют глубокий опыт
- Система имеет элементы новизны (работа с онтологией, семантический поиск)
- Требования частично жестко фиксированы, но есть гибкость в реализации
- Проект средней сложности

### 1.2. Расчет трудоемкости и времени разработки

**Исходные данные:**
- SIZE = 13.8 KSLOC
- Тип проекта: Полунезависимый

**Коэффициенты для полунезависимого типа:**
- a = 3.0
- b = 1.12
- c = 2.5
- d = 0.35

**Расчеты:**

**Трудоемкость (PM):**
```
PM = a × (SIZE)^b = 3.0 × (13.8)^1.12 = 3.0 × 18.47 = 55.41 чел×мес
```

**Время разработки (TM):**
```
TM = c × (PM)^d = 2.5 × (55.41)^0.35 = 2.5 × 4.45 = 11.13 мес ≈ 11 месяцев
```

**Средний размер команды:**
```
Средний размер команды = PM / TM = 55.41 / 11.13 = 4.98 ≈ 5 человек
```

### 2.2. Расчет EAF (Effort Adjustment Factor)

**Расчет произведения атрибутов стоимости:**

**Средний размер команды:**

Средний размер команды = PM / TM = 36.24 / 10.38 = 3.49 ≈ 3-4 человека

## 5. Выводы

1. **Наиболее точная оценка** - COCOMO II (Post Architecture): 30.64 чел×мес, 12.9 месяцев, команда 2-3 человека.

2. **Влияние факторов:**
   - Высокая квалификация команды снижает трудоемкость на 20-30%
   - Использование современных инструментов снижает трудоемкость на 10-15%
   - Сложность продукта (онтология, семантический поиск) увеличивает трудоемкость

3. **Рекомендации:**
   - Использовать оценку COCOMO II (Post Architecture) как основную
   - Учитывать риски: возможное увеличение трудоемкости на 20-30% при непредвиденных сложностях
   - Формировать команду из 2-3 разработчиков для оптимальной эффективности

4. **Сравнение с реальностью:**
   - Оценка соответствует реальной сложности проекта средней команды
   - Учет специфики работы с онтологией и семантическим поиском учтен через фактор сложности
