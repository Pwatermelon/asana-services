# Практическая работа 3. Оценка стоимости разработки на основе метода функциональных точек (FPA)

## Цель работы
Изучить основы применения метода функциональных точек для оценки стоимости разработки программного продукта "Каталог асан".

## Описание проекта

**Проект:** Веб-приложение "Каталог асан" - информационная система для хранения и управления информацией об асанах йоги.

## 1. Определение типа оценки

**Тип оценки:** Проект разработки - оценивается количество функциональности, поставляемой пользователям в первом релизе продукта.

## 5. Определение суммарного количества невыравненных функциональных точек (UFP)

**Расчет UFP:**
```
UFP = Σ(ILF) + Σ(EIF) + Σ(EI) + Σ(EO) + Σ(EQ)
UFP = 41 + 5 + 35 + 10 + 30 = 121 FP
```

## 6. Определение значения фактора выравнивания (VAF)

**Таблица 3.6 - Оценка 14 системных параметров**

| № | Системный параметр | Оценка (0-5) | Обоснование |
|---|-------------------|--------------|-------------|
| 1 | Обмен данными | 3 | Система обменивается данными с сервисом авторизации через REST API |
| 2 | Распределенная обработка данных | 4 | Микросервисная архитектура (Backend, Frontend, сервис авторизации, хранилище) |
| 3 | Производительность | 2 | Требования к времени отклика для веб-интерфейса (не критичные) |
| 4 | Ограничения по аппаратным ресурсам | 2 | Работа в Docker контейнерах, нет жестких ограничений |
| 5 | Транзакционная нагрузка | 2 | Количество одновременных пользователей среднее |

| 14 | Гибкость | 3 | Возможность расширения функционала, настройка системы |
| **Итого TDI** | | **42** | |

**Расчет VAF:**
```
TDI = 3 + 4 + 2 + 2 + 2 + 4 + 3 + 3 + 4 + 2 + 3 + 3 + 4 + 3 = 42
VAF = (TDI × 0.01) + 0.65 = (42 × 0.01) + 0.65 = 0.42 + 0.65 = 1.07
```

## 7. Расчет количества выровненных функциональных точек (AFP)

**Расчет AFP:**
```
AFP = UFP × VAF = 121 × 1.07 = 129.47 ≈ 130 FP
```

## 8. Оценка трудоемкости разработки

### 8.1. Оценка объема кода

**Таблица 3.7 - Количество строк кода на функциональную точку**

| Компонент | Язык | SLOC/FP | FP | SLOC |
|-----------|------|---------|----|----|
| Backend | Python | 46 | 65 | 2990 |
| Frontend | JavaScript | 24 | 65 | 1560 |
| **Итого** | | | **130** | **4550** |

**Расчет:**
- Backend: 130 FP × 0.5 (доля backend) × 46 SLOC/FP = 2990 SLOC
- Frontend: 130 FP × 0.5 (доля frontend) × 24 SLOC/FP = 1560 SLOC
- Общий объем: 4550 SLOC = 4.55 KSLOC

### 8.2. Использование COCOMO II для оценки трудоемкости

**Исходные данные:**
- SIZE = 4.55 KSLOC
- Тип проекта: Полунезависимый
- EAF = 0.654 (из Практической работы 2)

**Расчет трудоемкости:**
```
PM = 3.0 × (4.55)^1.12 × 0.654 = 3.0 × 5.23 × 0.654 = 10.26 чел×мес
```

**Расчет времени разработки:**
```
TM = 2.5 × (10.26)^0.35 = 2.5 × 2.38 = 5.95 мес ≈ 6 месяцев
```

## 9. Выводы

1. **Общее количество функциональных точек:** 130 FP
2. **Объем кода:** 4.55 KSLOC
3. **Трудоемкость разработки:** 10.26 чел×мес
4. **Время разработки:** 6 месяцев
5. **Средний размер команды:** 1.7 ≈ 2 человека

**Сравнение с реальным объемом проекта:**
- Реальный объем: ~13.8 KSLOC
- Оценка FPA: 4.55 KSLOC
- Расхождение связано с тем, что FPA учитывает только функциональность, а не инфраструктурный код, конфигурации, тесты

**Рекомендации:**
- Метод FPA дает заниженную оценку для проектов с большим объемом инфраструктурного кода
- Для более точной оценки следует использовать комбинацию методов FPA и COCOMO
