Обзор проекта

Источник: README/О_ПРОЕКТЕ/docker-compose/nginx
Идея
Объективный каталог асан
Асана определяется в контексте источника (книга/публикация), что снимает субъективность и позволяет сравнивать трактовки.
Архитектура
Nginx → Frontend/Backend/Auth
Reverse proxy маршрутизирует запросы в asana-frontend, asana-backend и server-module.
Хранилища
PostgreSQL + OWL + MinIO
Служебные данные в Postgres (схема dict_schema), предметные — в ontology_updated.owl, изображения — в MinIO S3.

Основные возможности

Собрано по README/курсовой

Каталог

  • Поиск по названиям (в т.ч. нечеткий).
  • Алфавитная навигация и фильтрация.
  • Просмотр карточки асаны и фото из разных источников.

Источники и контент

  • Управление источниками и привязка асан к источникам.
  • Мультиязычные названия: RU / санскрит / транслитерация / перевод.
  • Связи “похожие/аналогичные” асаны.

Импорт/экспорт и модерация

  • Импорт из Excel (в т.ч. фоновыми задачами с прогрессом).
  • Модерация конфликтов/дубликатов с интерфейсом для экспертов.
  • Экспорт модерации обратно в Excel.

Безопасность и роли

  • JWT и проверка прав через внешний сервис server-module.
  • Защищённые маршруты/страницы для экспертных функций.
  • Документация API (/docs) защищена middleware (доступ admin/expert).

Ключевое API

Источник: asana-dict-service/backend/app/main.py + nginx

Публичные (каталог)

  • GET /api/asanas — список асан
  • GET /api/asana/{asana_id} — детали асаны
  • GET /api/asanas/search?query=... — поиск
  • GET /api/sources — источники

Эксперт/Admin (контент)

  • POST /api/asana — добавить асану + фото
  • POST /api/sources — добавить источник
  • POST /api/import/* — импорт Excel (фоновые задачи + статус)
  • GET /api/moderation/items — модерация

Контент “О проекте”

  • GET /api/about-project — текст “О проекте”
  • GET /api/expert-instructions — инструкции эксперту
  • POST эти же endpoints — обновление (только admin)

Документация

  • /docs, /redoc, /openapi.json — защищены (нужна роль expert/admin).
  • Проверка токена идёт через server-module (см. diagram + nginx).

Данные и онтология

PostgreSQL + OWL + MinIO

PostgreSQL

  • Схема: dict_schema (для asana-dict-service).
  • Таблицы: users, moderation_items, about_project, expert_instructions.
  • Server-module использует основную схему (public) для своих данных.

OWL онтология

  • Файл: asana-dict-service/backend/ontology_updated.owl (монтируется в контейнер backend).
  • Ключевые сущности: Asana, AsanaSource, AsanaName, AsanaPhoto, SameAsObject.

MinIO (S3)

  • Хранение изображений асан.
  • Публичная раздача через /images/ (Nginx → MinIO).
  • Антидубликаты: вычисление хеша при загрузке (в коде backend).

Интеграции

  • Backend проверяет JWT через HTTP к server-module.
  • Фронтенд ходит в /api/... (за ним Nginx).

Роли пользователей

Источник: README/О_ПРОЕКТЕ

Гость

  • Просмотр каталога и поиск.
  • Просмотр источников, фото, описаний.

Эксперт

  • Добавление асан/источников, загрузка фото.
  • Импорт Excel и работа с модерацией.

Администратор

  • Полный доступ + управление пользователями.
  • Загрузка/обновление онтологии, системные настройки.

Как это реализовано

  • Nginx проксирует /api/auth и /api/users/me в server-module.
  • Backend дополнительно проверяет токен через AUTH_SERVICE_URL.

Как запускать (быстрый старт)

Без сборки страницы — это просто документация

Через Docker Compose

  • docker-compose up -d
  • После этого: http://localhost/ (через nginx:80)
  • Backend API: http://localhost/api/...
  • MinIO console: http://localhost:9001

Порты (по compose)

  • nginx: 80
  • asana-frontend: 3000
  • asana-backend: 8000
  • server-module: 8001→8000
  • postgres: 5432
  • minio: 9000/9001
